# بردن برنامه روی یک میزبان مجانی (Hugging Face Spaces)

**این پرونده برای خودت است، نه برای کارفرما.** این‌جا نوشته‌ام چطور در حدود پنج دقیقه برنامه را
روی یک فضای مجانی بالا بیاوری، بدون سرور، بدون دامنه و **بدون کارت بانکی**. حساب کاربری را باید
خودت بسازی (ثبت‌نام به ایمیل خودت نیاز دارد)، ولی همهٔ کار فنی آماده است.

## چه چیزی مجانی است و چه چیزی نیست (بی‌پرده)

| موضوع | واقعیت |
| --- | --- |
| هزینه | صفر. HF برای Space با CPU رایگان (۲ vCPU و ۱۶ گیگ رم) کارت بانکی نمی‌خواهد |
| نشانی | آدرس `https` روی دامنهٔ خودشان (`‎*.hf.space`) با گواهی SSL |
| داده | روی دیسک موقت (حدود ۵۰ گیگ)؛ **با هر بازسازی پاک می‌شود** |
| خواب رفتن | بعد از حدود ۴۸ ساعت بی‌کاری می‌خوابد؛ اولین بازدید ۳۰ تا ۹۰ ثانیه بیدارش می‌کند |
| خصوصی بودن | Space مجانی **عمومی** است؛ یعنی آدرسش برای همه باز است. پس دروازه باید روشن بماند و رمزها محرمانه |
| دادهٔ واقعی | **روی HF دادهٔ واقعی معاملات نگذار.** این نسخه برای نمایش و آزمون است |

## گام‌به‌گام

۱. **حساب بساز:** [huggingface.co/join](https://huggingface.co/join) (ایمیل و رمز؛ کارت نمی‌خواهد).

۲. **Space بساز:** [huggingface.co/new-space](https://huggingface.co/new-space)
   - **Name:** مثل `desk-station`
   - **SDK:** `Docker` · **Template:** `Blank`
   - **Space hardware:** `CPU basic · FREE`
   - **Visibility:** `Public` → بعد `Create Space`

۳. **بستهٔ آماده را بالا بگذار.** روی رایانهٔ خودت:

```bash
# ۱) بسته را بساز (همین یک فرمان؛ خروجی در MATERIALS/money/delivery/iran-desk-hf)
cd MATERIALS/money/gui/deploy
python3 make_hf.py --zip

# ۲) ابزار آپلود
pip install -U huggingface_hub
hf auth login          # توکن را از Settings → Access Tokens بساز و بچسبان

# ۳) آپلود
hf upload <نام‌کاربری>/desk-station ../../../delivery/iran-desk-hf . --repo-type space
```

روش جایگزین با git:

```bash
git clone https://huggingface.co/spaces/<نام‌کاربری>/desk-station
cp -r ../../../delivery/iran-desk-hf/. desk-station/
cd desk-station && git add -A && git commit -m "ایستگاه تصمیم مشتقه" && git push
```

۴. **پنج مقدار محرمانه** را در `Settings` → `Variables and secrets` → `New secret` بگذار:

| نام | مقدار |
| --- | --- |
| `STATION_ADMIN_ID` | شناسهٔ مدیر (مثل `mafhoom`) |
| `STATION_ADMIN_PASS` | رمز قوی پنل مدیریت (خودت بساز: ۱۲ نویسهٔ تصادفی) |
| `STATION_GUEST_ID` | شناسهٔ کارفرما (مثل `masoud`) |
| `STATION_GUEST_PASS` | رمز قوی کارفرما (این را به او می‌دهی) |
| `STATION_GUEST_OFF` | اختیاری: `1` یعنی کارفرما فعلاً نتواند وارد شود |

اگر این‌ها را نگذاری، برنامه موقع بالا آمدن **خودش رمز تصادفی می‌سازد و در گزارش (Logs) چاپ می‌کند** —
کار می‌کند، ولی رمز در گزارش می‌ماند؛ برای آزمون سریع خوب است، برای کار جدی نه.

۵. وقتی وضعیت Space روی `Running` رفت، این آدرس را باز کن و یک‌بار خودت با حساب مدیر وارد شو:

```
https://<نام‌کاربری>-desk-station.hf.space/login
```

بعد همان آدرس `‎/login` را با **رمز کارفرما** برایش بفرست. رمز مدیر را هرگز نفرست.

## مهم: دو راه HF داریم و یکی از آن‌ها مجانی است

آزمودیم (۲۲ سپتامبر ۲۰۲۶): Space **داکری** روی حساب مجانی HF پاسخ ۴۰۲ می‌دهد و اشتراک PRO لازم
دارد. ولی Space **ایستا** برای همه مجانی است. پس دو ابزار داریم:

| راه | فرمان | چه می‌دهد |
| --- | --- | --- |
| نمونهٔ ثابت (مجانی) | `./activate_demo_site.sh` | خودِ رابط + تمام خروجی‌های واقعی، روی یک لینک عمومی ثابت، بدون کارتی |
| برنامهٔ زندهٔ داکری | `./activate_hf.sh` | اگر روزی PRO داشتی: سرور کامل با دروازهٔ ورود و دادهٔ زنده |

نمونهٔ ثابت از این‌ها ساخته می‌شود: `tools/record_static_demo.mjs` (ضبط پاسخ‌های واقعی در حاشیهٔ
همان آزمون ۱۹۲ بررسی) → `deploy/make_demo_site.py` (ساخت سایت ایستا + لایهٔ پاسخ‌های ضبط‌شده) →
`deploy/huggingface/activate_demo_site.py` (نشر + آزمودن زنده با `tools/check_demo_site.mjs`).

## آزمودن سمت خودت (پیش از آپلود)

خود `boot.sh` همان کاری را می‌کند که HF می‌کند؛ می‌توانی محلی هم بیازمایی:

```bash
cd ../../../delivery/iran-desk-hf
STATION_ADMIN_PASS='<رمز-آزمون-مدیر>' STATION_GUEST_ID=masoud STATION_GUEST_PASS='<رمز-آزمون-کارفرما>' \
  STATION_PORT=7860 bash boot.sh
# در مرورگر: http://127.0.0.1:7860   (بدون ورود ۴۰۱ · با حساب کارفرما ۲۰۰ · پنل مدیر ۴۰۳ برای کارفرما)
```

## بیدار نگه داشتن (اختیاری، مجانی)

Space مجانی بعد از حدود ۴۸ ساعت بی‌کاری می‌خوابد. اگر می‌خواهی همیشه بیدار باشد، در یک سرویس
زمان‌بند مجانی (مثل cron-job.org) یک کار بساز که هر یک ساعت آدرس `https://<...>.hf.space/login`
را باز کند. این کار هم مجانی است، ولی تضمین آپ‌تایم نمی‌دهد.

## خاموش کردن و حذف

- **خاموش موقت:** در `Settings` → `Pause this Space`
- **حذف کامل:** در `Settings` → `Delete this Space`
- **قطع فقط کارفرما، بدون خواباندن برنامه:** `STATION_GUEST_OFF=1` را در Secrets بگذار (یا در
  پنل مدیریت نشست‌های مهمان را ببند)

هیچ‌چیز این‌جا گروگان نیست: هر وقت سرور یا دامنهٔ خودت را آوردی، همین برنامه را با پوشهٔ `deploy/`
روی آن ببر و Space را حذف کن؛ داده و رمزها سمت خودت می‌مانند.

## اگر HF را نخواستی: Render

`deploy/render/render.yaml` هم گذاشته‌ام (یک میزبان مجانی دیگر، بدون کارت بانکی). فرقش: فقط
۵۱۲ مگ رم و ۰٫۱ پردازنده دارد، **بعد از ۱۵ دقیقه بی‌کاری می‌خوابد** و بیدار شدنش ۳۰ تا ۶۰ ثانیه
طول می‌کشد؛ برای نمایش زندهٔ نیم‌ساعته خوب نیست، برای تست‌های گاه‌به‌گاه به‌کار می‌آید. راهش:
کد را روی یک مخزن GitHub بگذار و در Render گزینهٔ `Blueprint` را انتخاب کن.

> **پرسش باز:** اگر حساب HF یا GitHub داری و می‌خواهی خودم گام‌ها را با تو جلو ببرم، بگو کدام گام
> گیر کردی؛ ولی ساختن حساب و زدن توکن باید دست خودت باشد (رمز و ایمیل تو را نمی‌پرسم).
